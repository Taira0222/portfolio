# 要件定義: Qiita最新記事プレビュー機能

## TL;DR (要約)
このドキュメントは、ポートフォリオサイトに「Qiitaの最新記事3件を自動表示する機能」を追加するための設計書です。

- **何を作る**: Blogセクション（カード型UI）
- **どこに表示**: Homeページ（PortfolioとCareerの間）
- **データ元**: Qiita API v2から自動取得
- **対応デバイス**: デスクトップ（3カラム）/ タブレット（2カラム）/ スマホ（1カラム）
- **主な機能**: 記事タイトル・要約・リンク表示、多言語対応、エラーハンドリング

---

## 1. 機能概要
ポートフォリオサイトにQiitaブログの最新記事を表示する新規セクションを追加し、訪問者に技術的な活動をアピールする。

## 2. 目的・背景
- Qiitaでの技術発信活動をポートフォリオサイトでも可視化
- 「毎日投稿1年間達成」という実績を活かし、最新の学習内容を示す
- ポートフォリオサイトとQiitaブログの連携を強化

## 3. 機能要件

### 3.1 表示仕様

#### 3.1.1 配置場所
- **セクション名**: Blog
- **表示位置**: Homeページ内の新規セクション
- **セクション順序**: `Hero → About → TechStack → Portfolio → Blog → Career`

#### 3.1.2 表示内容
- **記事件数**: 最新3件
- **必須表示項目**:
  - 記事タイトル
  - 記事の要約文（150文字程度）
  - 記事へのリンク（Qiitaページへ遷移）

#### 3.1.3 表示形式
- カード型UIで各記事を表示
- グリッドレイアウト:
  - デスクトップ: 3カラム（横並び）
  - タブレット: 2カラム
  - モバイル: 1カラム（縦並び）

### 3.2 データ取得仕様

#### 3.2.1 データソース
- Qiita REST API v2 を使用
- エンドポイント: `GET https://qiita.com/api/v2/users/{username}/items`
- 認証: 不要（公開記事の取得のみ）

#### 3.2.2 取得条件
- パラメータ:
  - `per_page`: 3
  - `page`: 1
  - ソート順: デフォルト（作成日時降順）

#### 3.2.3 取得データ
APIから以下のフィールドを取得:
- `id`: 記事ID
- `title`: 記事タイトル
- `url`: 記事URL
- `body`: 記事本文（要約生成用）

#### 3.2.4 要約文の生成ロジック
- 記事本文（`body`）からmarkdown記法を除去
- 先頭150文字を抽出
- 150文字を超える場合は「...」を末尾に追加

### 3.3 UI/UX要件

#### 3.3.1 デザイン方針
- 既存のPortfolio/Careerセクションとデザインの統一性を保つ
- グラデーション背景とぼかし効果で視覚的な一貫性を維持
- framer-motionでfade-upアニメーション

#### 3.3.2 レスポンシブ対応
- ブレークポイント:
  - モバイル: ~768px（1カラム）
  - タブレット: 768px~1024px（2カラム）
  - デスクトップ: 1024px~（3カラム）

#### 3.3.3 アニメーション
- セクション表示時: fade-up（既存セクションと同様）
- カードホバー: 軽微なスケール/影の変化
- ローディング時: スケルトンスクリーンまたはスピナー

### 3.4 状態管理要件

#### 3.4.1 ローディング状態
- API取得中はローディングインジケーターを表示
- ユーザーに待機状態を明確に伝える

#### 3.4.2 エラーハンドリング
- API取得失敗時:
  - エラーメッセージを表示
  - リトライボタンの提供（オプション）
- ネットワークエラー、タイムアウトに対応

#### 3.4.3 空データ対応
- 記事が0件の場合:
  - 「記事が見つかりませんでした」メッセージを表示
  - Qiitaプロフィールページへのリンクを提供（オプション）

### 3.5 多言語対応要件

#### 3.5.1 対応言語
- 日本語（ja）
- 英語（en）

#### 3.5.2 翻訳対象
- セクションタイトル・説明文
- ローディング/エラーメッセージ
- ボタンラベル（「記事を読む」等）
- ナビゲーションメニュー

#### 3.5.3 記事コンテンツ
- 記事タイトル・要約は翻訳せず、Qiitaの元データをそのまま表示

### 3.6 ナビゲーション要件
- ヘッダーのナビゲーションメニューに「Blog」を追加
- クリックでBlogセクションへスムーススクロール
- モバイルハンバーガーメニューにも追加

## 4. 非機能要件

### 4.1 パフォーマンス
- 初回ロード時のAPI取得時間: 3秒以内
- ページロード時の体感速度を損なわない

### 4.2 アクセシビリティ
- セマンティックHTML（`<article>`, `<section>` 等）
- キーボードナビゲーション対応
- スクリーンリーダー対応（aria-label等）

### 4.3 SEO
- 適切なセマンティックマークアップ
- meta情報への記事情報の反映（オプション）

### 4.4 ブラウザ対応
- モダンブラウザ（Chrome, Firefox, Safari, Edge）の最新版
- 既存サイトの対応ブラウザに準拠

## 5. 制約条件

### 5.1 技術的制約
- Qiita API v2の仕様に準拠
- レート制限: 認証なしの場合は60リクエスト/時間
- APIレスポンスにdescriptionフィールドが存在しないため、bodyから要約を生成

### 5.2 運用上の制約
- Qiitaユーザー名は設定ファイルまたは環境変数で管理
- API障害時も既存セクションには影響を与えない

## 6. 成功指標
- Blogセクションが既存デザインと違和感なく統合されている
- API取得エラー時も適切にハンドリングされている
- モバイル/タブレット/デスクトップで表示が最適化されている
