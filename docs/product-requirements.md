# プロダクト要求定義書（Product Requirements Document）

## 1. プロダクトビジョンと目的

### ビジョン
開発者のスキル、プロジェクト実績、キャリアを効果的に紹介するモダンでインタラクティブなポートフォリオサイトを提供し、訪問者に強い印象を与える。

### 目的
- 技術スキルとプロジェクト実績を視覚的にわかりやすく伝える
- エンジニアとしての経歴と成長過程を時系列で紹介する
- 多言語対応により、国内外の採用担当者や協業パートナーにアプローチする
- モダンなフロントエンド技術を活用し、技術力を実証する

## 2. ターゲットユーザーと課題・ニーズ

### ターゲットユーザー
- **採用担当者**: エンジニアのスキルセットとプロジェクト実績を確認したい企業の人事・技術責任者
- **技術責任者**: 技術スタックの適合性とコードの品質を評価したいエンジニアリングマネージャー
- **協業パートナー**: フリーランス・業務委託の依頼を検討している企業やスタートアップ
- **同業エンジニア**: ポートフォリオのデザインや実装の参考にしたい開発者

### 課題とニーズ
- **課題1**: 履歴書や職務経歴書だけでは、実際のスキルレベルや技術的な強みが伝わりにくい
- **ニーズ1**: 実際のプロジェクト成果物や使用技術を視覚的に提示できるプラットフォーム

- **課題2**: GitHub や履歴書のテキスト情報だけでは、エンジニアの人間性やキャリアストーリーが見えにくい
- **ニーズ2**: 経歴の背景やモチベーション、成長の軌跡を伝えられる場

- **課題3**: 英語圏の企業や国際的なプロジェクトへアプローチする際の言語障壁
- **ニーズ3**: 日本語・英語両方で情報を提供できる多言語対応サイト

## 3. 主要な機能一覧

### 基本機能
1. **Hero セクション**: インパクトのあるファーストビューと自己紹介
2. **About セクション**: プロフィール情報と経歴概要の表示
3. **Tech Stack セクション**: 技術スキルをカテゴリ別に整理して表示
4. **Portfolio セクション**: プロジェクト実績をカルーセル形式で紹介
5. **Career セクション**: キャリアの時系列タイムラインを表示

### UI/UX 機能
6. **レスポンシブデザイン**: モバイル・タブレット・デスクトップ対応
7. **スムーズスクロール**: セクション間のシームレスな遷移
8. **アニメーション**: Framer Motion を活用した視覚効果
9. **多言語切替**: 日本語/英語のリアルタイム切替（i18next）
10. **ナビゲーション**: 固定ヘッダーとハンバーガーメニュー

### インタラクション機能
11. **プロジェクト詳細表示**: Dialog で各プロジェクトの詳細情報を表示
12. **SNS リンク**: GitHub, LinkedIn, X(Twitter), Qiita への外部リンク
13. **トップへ戻るボタン**: フッターからワンクリックでページトップへ移動

## 4. 成功の定義

### ビジネスゴール
- エンジニアとしての技術力とプロジェクト実績を効果的にアピールできる
- 採用担当者や協業パートナーからのコンタクト獲得
- 技術ブログやSNSへの誘導によるエンゲージメント向上
- ポートフォリオサイト自体が技術力を証明する成果物となる

### 定量的指標（KPI）
- **パフォーマンス**: 初回ロード時間が2秒以内
- **品質スコア**: Lighthouse スコアで Performance, Accessibility, Best Practices, SEO すべて 90 点以上
- **レスポンシブ対応**: モバイル・タブレット・デスクトップすべてで快適に動作
- **操作性**: 全セクションへのスクロール・遷移が1秒以内に完了
- **外部リンククリック率**: Portfolio セクションからの外部リンク（GitHub, ライブサイト）クリック率 30% 以上
- **言語切替利用率**: 英語表示への切替が全訪問者の 20% 以上

### 定性的指標
- 訪問者が直感的に操作でき、情報を素早く把握できる
- モダンで洗練されたデザインによる好印象
- アニメーションが自然で過度にならず、UX を損なわない
- 技術力を視覚的・実践的に伝えられる
- 採用担当者からの好意的なフィードバック

## 5. ビジネス要件

### 技術的制約
- フロントエンドのみで動作（静的サイト）
- React 19 + TypeScript + Vite で構築
- Tailwind CSS を使用したモダンなデザイン
- GitHub Pages でホスティング（サブパス `/portfolio/` 対応）

### 予算・リソース
- 個人開発プロジェクトのため、外部コスト0円
- オープンソースライブラリのみ使用
- ホスティング費用: 無料（GitHub Pages）

### デプロイメント
- 自動デプロイ: GitHub Actions による CI/CD
- ホスティング環境: GitHub Pages
- カスタムドメイン対応可能（将来的に）

### スケジュール・マイルストーン
- **フェーズ1（完了）**: 基本5セクション実装（Hero, About, Tech Stack, Portfolio, Career）
- **フェーズ2（完了）**: 多言語対応（日本語/英語）、レスポンシブデザイン
- **フェーズ3（完了）**: アニメーション・インタラクション実装
- **フェーズ4（現在）**: パフォーマンス最適化、SEO対策、アクセシビリティ向上
- **フェーズ5（将来）**: カスタムドメイン導入、アナリティクス統合、お問い合わせフォーム追加検討

## 6. ユーザーストーリー

### ストーリー1: プロフィールを確認する
**As a** 採用担当者
**I want to** エンジニアのプロフィールと経歴概要を確認できる
**So that** 候補者の基本情報を素早く把握できる

### ストーリー2: 技術スキルを確認する
**As a** 技術責任者
**I want to** 候補者の技術スタックを体系的に確認できる
**So that** 自社のプロジェクトに適合するか判断できる

### ストーリー3: プロジェクト実績を閲覧する
**As a** 協業パートナー候補
**I want to** 過去のプロジェクト実績を詳しく見る
**So that** どのような成果物を作れるエンジニアか理解できる

### ストーリー4: キャリアの背景を理解する
**As a** 採用担当者
**I want to** 候補者のキャリアの変遷を時系列で確認できる
**So that** どのような経験を積んできたか、モチベーションを理解できる

### ストーリー5: 言語を切り替える
**As a** 海外企業の採用担当者
**I want to** サイトを英語で閲覧できる
**So that** 内容を理解しやすくなる

### ストーリー6: モバイルデバイスで閲覧する
**As a** 移動中の採用担当者
**I want to** スマートフォンやタブレットで快適に閲覧できる
**So that** いつでもどこでも候補者の情報を確認できる

### ストーリー7: SNS・外部リンクにアクセスする
**As a** 技術責任者
**I want to** GitHub、LinkedIn、技術ブログなどの外部リンクにアクセスできる
**So that** より詳細な技術情報やコード品質を確認できる

## 7. 受け入れ条件

### ストーリー1の受け入れ条件
- Hero セクションで名前とキーワードが表示される
- About セクションでプロフィール画像と自己紹介文が読める
- スクロールまたはナビゲーションで各セクションへ移動できる
- ナビゲーションメニューがすべてのセクションで利用可能

### ストーリー2の受け入れ条件
- Tech Stack セクションでフロントエンド、バックエンド、データベース、CI/CD、インフラ、テストの6カテゴリに技術が整理されている
- 各技術のアイコンと名称が視覚的にわかりやすく表示される
- 使用経験のある技術が一目で把握できる
- カテゴリごとにグリッドレイアウトで整理されている

### ストーリー3の受け入れ条件
- Portfolio セクションでプロジェクトがカルーセル形式で表示される
- 各プロジェクトのサムネイル、タイトル、カテゴリ、概要が見られる
- プロジェクトカードをクリックすると詳細情報（技術スタック、役割、ハイライト、リンク）が Dialog で表示される
- 実際のアプリケーションや GitHub リポジトリ、技術記事へのリンクがある
- カルーセルの前後ナビゲーションボタンが機能する

### ストーリー4の受け入れ条件
- Career セクションでタイムライン形式でキャリアが表示される
- 各マイルストーンに日付、タイトル、説明、画像が含まれる
- 時系列（古い順または新しい順）で成長の過程が追える
- 視覚的に見やすいタイムラインデザイン

### ストーリー5の受け入れ条件
- ヘッダーに言語切替ボタン（日本語/英語）がある
- 言語をクリック1回で切り替えられる
- 選択した言語設定が localStorage に保存され、再訪問時も維持される
- すべてのセクション、ナビゲーション、ボタンテキストが選択言語で表示される
- ブラウザの言語設定に基づいて初回表示言語が自動選択される

### ストーリー6の受け入れ条件
- 画面幅 320px（iPhone SE）から 4K（3840px）まで対応
- モバイルデバイスではハンバーガーメニューが表示される
- タッチ操作でカルーセルやスクロールが快適に動作する
- テキストや画像が画面サイズに応じて適切にリサイズされる
- モバイルでもすべての機能にアクセス可能

### ストーリー7の受け入れ条件
- ヘッダーとフッターに GitHub, LinkedIn, X(Twitter), Qiita へのリンクがある
- Portfolio セクションの各プロジェクトに外部リンク（ライブサイト、リポジトリ、記事）がある
- リンクをクリックすると新しいタブで開かれる（`target="_blank"`）
- リンクアイコンが視覚的にわかりやすい

## 8. 機能要件

### 8.1 Hero セクション
- インタラクティブな背景アニメーション
- 名前とキャッチコピーの表示
- スクロールトリガーで次セクションへ誘導

### 8.2 About セクション
- プロフィール画像の表示
- 経歴概要テキストの表示
- グラデーション背景とカードレイアウト

### 8.3 Tech Stack セクション
- 6つのカテゴリ（フロントエンド、バックエンド、データベース、CI/CD、インフラ、テスト）
- 各技術のアイコンとバッジ表示
- カテゴリごとのグリッドレイアウト

### 8.4 Portfolio セクション
- Embla Carousel による横スクロール表示
- プロジェクトカード（画像、タイトル、カテゴリ、概要）
- Dialog による詳細情報の表示
- 外部リンク（ライブサイト、GitHub、記事）

### 8.5 Career セクション
- タイムライン形式のレイアウト
- 各マイルストーンの日付、タイトル、説明、画像
- 時系列でのビジュアル表現

### 8.6 ナビゲーション機能
- 固定ヘッダー（スクロール連動）
- デスクトップ: 通常メニュー表示
- モバイル: ハンバーガーメニュー
- 各セクションへのスムーズスクロール

### 8.7 多言語対応機能
- i18next による翻訳管理
- ヘッダーでの言語切替UI
- localStorage による言語設定の永続化
- ブラウザ言語の自動検出

### 8.8 レスポンシブデザイン機能
- ブレークポイント: sm (640px), md (768px), lg (1024px), xl (1280px)
- モバイルファーストのレイアウト
- タッチデバイス対応

### 8.9 フッター機能
- SNSリンク（GitHub, LinkedIn, X, Qiita）
- トップへ戻るボタン
- コピーライト表示

## 9. 非機能要件

### 9.1 パフォーマンス
- 初回ロード時間: 2秒以内
- セクション遷移のレスポンス: 500ms以内
- アニメーションのフレームレート: 60fps維持
- Lighthouse Performance スコア: 90点以上
- 画像の最適化（WebP形式、遅延読み込み）
- JavaScriptバンドルサイズ: 500KB以内（gzip圧縮後）

### 9.2 ユーザビリティ
- 直感的なナビゲーション設計
- マニュアルなしで操作可能
- アクセシビリティ対応（WAI-ARIA、キーボード操作、スクリーンリーダー対応）
- 明瞭なコントラスト比（WCAG AA準拠）
- フォーカス状態の視覚的フィードバック

### 9.3 互換性
- モダンブラウザ対応（Chrome, Firefox, Safari, Edge 最新2バージョン）
- iOS Safari 14+, Android Chrome 最新版対応
- モバイル・タブレット・デスクトップ対応
- 画面サイズ: 320px（iPhone SE）〜 4K（3840px）対応

### 9.4 SEO・検索エンジン最適化
- セマンティックHTML（header, nav, section, article, footer）
- メタタグの最適化（title, description, keywords）
- Open Graph 対応（SNSシェア時のプレビュー）
- 構造化データ（JSON-LD）の実装
- robots.txt、sitemap.xml の設置
- 適切な見出し階層（h1, h2, h3）

### 9.5 保守性
- TypeScript による型安全性
- コンポーネント単位での設計（Single Responsibility Principle）
- ESLint、Prettier によるコード品質管理
- 明確なディレクトリ構造（features, components, lib, hooks）
- コードコメントとドキュメント整備
- 命名規則の統一（CLAUDE.md の glossary.md 参照）

### 9.6 拡張性
- 新しいセクションの追加が容易（セクションベースアーキテクチャ）
- プロジェクトの追加が容易（データ駆動設計）
- 新言語の追加が容易（i18next の翻訳ファイル追加のみ）
- カスタムドメインへの移行が容易（basename設定の変更のみ）
- バックエンド連携を考慮した設計（将来的なAPI統合）

### 9.7 セキュリティ
- XSS攻撃対策（React のデフォルトエスケープ機能）
- 外部リンクのセキュリティ（`rel="noopener noreferrer"`）
- HTTPS通信（GitHub Pages デフォルト）
- 依存パッケージの脆弱性スキャン（npm audit）
